# Phase 10 — freezing the contract at v1.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze the public contract at 1.0.0 — fix the compatibility mechanism to allow 1.x, re-export the types a consumer needs, align the last two identity schemas, then bump.

**Architecture:** Four groups in a mandatory order. Group 1 fixes `isRuntimeCompatible` and every fixture/document pinned to the 0.x band — it has to finish first, because every later group runs under the new band. Group 4 bumps the number last, once everything already runs at 1.x.

**Tech Stack:** TypeScript (ESM, NodeNext), Vitest, Commander, JSON Schema — all already present.

Spec: `docs/superpowers/specs/2026-08-03-v1.0-contract-freeze-design.md`. Baseline: `main` @ `2f2a118`.
Branch: `feat/phase10-v1-contract-freeze` off that commit (project convention: branch + FF-merge, as every phase 3–9 did).

## Global Constraints

- **TDD.** Write the test, RUN it, paste the real failure into the report, and only then implement.
- **Every test proven by mutation:** delete or invert the line it covers, watch it go red, restore. Report each mutation and its observed failure. **If a mutation reddens fewer lines than the number of lines you added, that shortfall is itself a finding.**
- **No publishing.** No release workflow, no CHANGELOG, no tag, no `prepublishOnly`, no `repository`/`publishConfig`.
- No new runtime dependency, exit code, or artifact type. No semver parser.
- ESM: every relative import ends in `.js`. No snapshots.
- **Comments citing another file name the FILE, not a line number.** This project has been bitten five times by comment rot.
- **`git add` BEFORE `npm run scan:secrets`** — the scanner walks `git ls-files`, and has twice recorded a spurious passing scan because a file was untracked.
- **Never background a gate command and end your turn** — nothing will wake you back up.
- **The gate is nine commands, from a deleted `dist/`:**

  Coverage floor 90/80/95/90. Baseline at `2f2a118`: 1363/1363 tests (92 files), coverage 94.46/84.84/98.22/94.46.
- Conventional commit prefix; every message ends with:

### Task 1: The 1.x compatibility band and the test that never existed

**Files:**
- Modify: `src/installer/manifest.ts:8` (the band), `:49-53` (regex + doc comment)
- Create: `tests/installer/compatibility.test.ts`

**Interfaces:**
- Produces: `runtimeCompatibility === ">=1.0.0 <2.0.0"`; `isRuntimeCompatible` accepts 1.x and refuses 0.x. Every later task writes its fixtures under this band.

**Measured context — this is why this task goes first.** Today:

```ts
export const runtimeCompatibility = ">=0.1.0 <1.0.0";

/** The MVP deliberately supports its published pre-1.0 runtime line only. */
export function isRuntimeCompatible(version: string, range = runtimeCompatibility): boolean {
  if (range !== runtimeCompatibility) return false;
  return /^0\.[1-9]\d*\.\d+(?:-[0-9A-Za-z.-]+)?$/.test(version);
}
```

Two gating layers, and **no test calls this function directly** — `grep -rn "isRuntimeCompatible"` points at 3 `src/` files and prose in the spec, nothing else. The `range !== runtimeCompatibility` line has never been touched by any assertion.

- [ ] **Step 1: Write the failing test**

Create `tests/installer/compatibility.test.ts`:

```ts
import { describe, expect, it } from "vitest";

import { isRuntimeCompatible, runtimeCompatibility } from "../../src/installer/manifest.js";

/** This function decides whether every installer command can run at all, and before Phase 10 no
 *  test called it directly — neither gating layer was touched by any assertion. That is why moving
 *  the band to 1.x can break `runtime verify`, `skills install` and `readManifest` while the test
 *  suite stays green (every installer test resolves a fake binary printing 0.1.0; see runtime-fixture.ts). */
describe("isRuntimeCompatible", () => {
  it("accepts the 1.x line this build publishes", () => {
    expect(isRuntimeCompatible("1.0.0")).toBe(true);
    expect(isRuntimeCompatible("1.4.2")).toBe(true);
    expect(isRuntimeCompatible("1.0.0-rc.1")).toBe(true);
  });

  it("refuses the superseded 0.x line", () => {
    expect(isRuntimeCompatible("0.3.0")).toBe(false);
    expect(isRuntimeCompatible("0.1.0")).toBe(false);
  });

  it("refuses the next major and strings that are not versions", () => {
    expect(isRuntimeCompatible("2.0.0")).toBe(false);
    expect(isRuntimeCompatible("nope")).toBe(false);
    expect(isRuntimeCompatible("")).toBe(false);
  });

  // Second gating layer: any range other than the literal is refused, INCLUDING a correct one.
  // This is pre-existing behaviour, not something Phase 10 adds — but it has never been pinned.
  it("refuses every range other than the literal, including a semantically correct one", () => {
    expect(isRuntimeCompatible("1.0.0", ">=1.0.0 <2.0.0")).toBe(runtimeCompatibility === ">=1.0.0 <2.0.0");
    expect(isRuntimeCompatible("1.0.0", "^1.0.0")).toBe(false);
    expect(isRuntimeCompatible("1.0.0", ">=0.1.0 <1.0.0")).toBe(false);
  });
});
```

